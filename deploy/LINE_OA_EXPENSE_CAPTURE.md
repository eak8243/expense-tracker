# ข้อเสนอ: เพิ่มรายการค่าใช้จ่ายผ่าน LINE Official Account

ระบบสามารถรับข้อมูลจาก LINE Official Account แล้วสร้าง **รายการค่าใช้จ่ายสถานะร่าง** ให้เจ้าของรายการตรวจสอบใน Expense Tracker ก่อนบันทึกจริงได้ LINE Messaging API ส่ง webhook มายัง server เมื่อผู้ใช้ส่งข้อความหรือไฟล์ และสามารถดึงรูป/ไฟล์ด้วย message ID ได้ จึงรองรับการส่งใบเสร็จจากมือถือโดยตรง [1] [2]

> **หลักการสำคัญ:** ห้ามสร้างรายการแบบเบิกแล้วหรือได้รับเงินแล้วจาก LINE โดยอัตโนมัติ การรับจาก LINE ต้องสร้างได้สูงสุดเป็น **ร่าง** และให้ผู้ใช้ยืนยันรายละเอียดในระบบก่อน เพื่อป้องกันยอดเงิน บริษัท หรือหมวดหมู่ผิดพลาด

## รูปแบบที่เลือกได้

| แนวทาง | วิธีใช้งานของพนักงาน | ข้อดี | ข้อจำกัด | ความซับซ้อน |
|---|---|---|---|---|
| **A. เมนู LINE เปิดแบบฟอร์มมือถือ** | กด Rich Menu “เพิ่มค่าใช้จ่าย” แล้วเปิดหน้า form บนมือถือ | ข้อมูลครบ, ตรวจสอบง่าย, ลดการตีความข้อความผิด | ต้องเปิดหน้า form สั้น ๆ | ต่ำ–กลาง |
| **B. พิมพ์ข้อความ/ส่งรูปในแชต** | ส่งข้อความตามรูปแบบและแนบใบเสร็จให้ OA | เร็วที่สุด, ไม่ต้องเปิดฟอร์ม | ต้องออกแบบคำสั่งและขั้นตอนแก้ไข | กลาง |
| **C. แชต + อ่านใบเสร็จอัตโนมัติ** | ส่งรูปใบเสร็จ แล้วระบบเสนอรายการ/ยอดให้ยืนยัน | ลดการกรอกข้อมูลมากที่สุด | มีต้นทุน AI/OCR และต้องมีขั้นตอนยืนยันเข้มงวด | สูง |

**คำแนะนำ:** เริ่มด้วย **A** หากต้องการความถูกต้องสูงและใช้งานง่าย หรือเริ่มด้วย **B** หากต้องการบันทึกอย่างรวดเร็วในแชต จากนั้นค่อยเพิ่ม **C** หลังมีข้อมูลรูปแบบใบเสร็จเพียงพอ

## โครงสร้างที่แนะนำ

```text
LINE OA → HTTPS Webhook → ตรวจลายเซ็นและกัน event ซ้ำ
                          ↓
                     ตรวจบัญชี LINE ที่เชื่อมไว้
                          ↓
             สร้าง Expense Draft + จัดเก็บไฟล์แนบ
                          ↓
        ตอบกลับ LINE พร้อมลิงก์ตรวจสอบ/ยืนยันใน Expense Tracker
```

LINE กำหนดให้ webhook endpoint เป็น HTTPS และแนะนำให้ตรวจสอบ signature ก่อนประมวลผล เพื่อป้องกัน request ปลอม นอกจากนี้ webhook อาจถูกส่งซ้ำได้ จึงต้องเก็บ `webhookEventId` เป็น unique key เพื่อทำให้กระบวนการ idempotent [1]

## Flow ที่แนะนำสำหรับแนวทาง A: LINE Mini App / LIFF Form

ผู้ใช้กดเมนู **“เพิ่มค่าใช้จ่าย”** จาก Rich Menu ของ LINE OA แล้วเปิดหน้า mobile form ของ Expense Tracker หน้า form ตรวจ LINE user ID, ตรวจว่าเชื่อมกับบัญชีระบบแล้ว, เติมชื่อผู้ใช้และบริษัทที่เลือกไว้, ให้กรอกรายการ/ยอด/วันที่/หมวดหมู่/วิธีชำระ, และถ่ายหรือเลือกรูปใบเสร็จได้ เมื่อกดบันทึก ระบบสร้าง expense สถานะ `draft` พร้อมไฟล์แนบ แล้วตอบกลับหน้าสำเร็จและส่งลิงก์ไปยังรายการดังกล่าว

แนวทางนี้ใช้ flow การกรอกข้อมูลเดิมของ Expense Tracker จึงลด risk จากการอ่านข้อความ และสามารถใช้ date format ภาษาไทย, validation ยอดเงิน, และ upload validation เดิมได้ทันที

## Flow ที่แนะนำสำหรับแนวทาง B: บันทึกผ่านข้อความ LINE

หลังเชื่อมบัญชีแล้ว ผู้ใช้ส่งข้อความดังตัวอย่าง พร้อมแนบรูปใบเสร็จได้:

```text
เพิ่มค่าใช้จ่าย
บริษัท: Boonrawd Brewery
รายการ: อาหารกลางวัน
ยอด: 120
วันที่: 15/08/2569
ร้านค้า: ร้านตัวอย่าง
หมวดหมู่: อาหาร
ชำระ: PromptPay
```

ระบบ parse ข้อมูล, ตรวจสอบบริษัท/หมวดหมู่/วิธีชำระจากของผู้ใช้, ดาวน์โหลดไฟล์จาก LINE ทันที, สร้าง expense แบบ draft แล้วตอบ Flex Message สรุป เช่น “สร้างร่าง EXP-2026-000123 แล้ว” พร้อมปุ่ม **ตรวจสอบรายการ** และ **ยกเลิก**  ข้อความหรือรูปที่ผู้ใช้ส่งสามารถมี event ซ้ำได้ จึงต้องใช้ `webhookEventId` เพื่อไม่ให้สร้าง expense ซ้ำ [1]

## การเชื่อมบัญชีและสิทธิ์

ต้องไม่เชื่อม LINE user ID กับ user ในระบบโดยอัตโนมัติจากชื่อ display name ให้ผู้ใช้ login ด้วยบัญชี Expense Tracker หนึ่งครั้ง แล้วกดยืนยันเชื่อมบัญชี LINE จากหน้า Profile หรือผ่าน one-time link ที่ OA ส่งให้ หลังยืนยันให้บันทึก `lineUserId` กับ `userId` แบบ one-to-one และ admin ต้องมีหน้าจอสำหรับดู/ยกเลิก/แก้ไขการเชื่อมบัญชีได้

| ตารางใหม่ | วัตถุประสงค์ | ข้อกำหนดสำคัญ |
|---|---|---|
| `line_user_links` | ผูก LINE `userId` กับ user ระบบ | unique ทั้ง `lineUserId` และ `userId`, เก็บเวลาเชื่อม |
| `line_webhook_events` | กัน event ซ้ำและติดตาม error | unique `webhookEventId`, เก็บ event type, status และเวลา |
| `line_capture_sessions` | เก็บ draft/สถานะการรับข้อมูล | ผูกกับ user, expense, message ID และเวลาหมดอายุ |

## ความปลอดภัยและความเป็นส่วนตัว

Channel secret และ channel access token ต้องเก็บเป็น server-side secret เท่านั้น ห้ามส่งลง client, Git หรือข้อความแชต ระบบต้องตรวจ `x-line-signature` ด้วย HMAC-SHA256 ก่อนใช้ payload และตอบ 2xx หลังรับ event ที่ตรวจสอบแล้ว LINE ระบุด้วยว่าควรดึงไฟล์ที่ผู้ใช้ส่งโดยเร็ว เพราะ content จะถูกลบอัตโนมัติหลังช่วงเวลาหนึ่ง [1]

เมื่อผู้ใช้ unsend ข้อความหรือไฟล์ LINE จะส่ง unsend event มา ระบบควรยกเลิก draft ที่ยังไม่ยืนยันและลบไฟล์ชั่วคราวของ event นั้น เพื่อเคารพเจตนาของผู้ใช้ [1]

## สิ่งที่ต้องตั้งค่าจาก LINE Developers

| รายการ | ใช้ทำอะไร |
|---|---|
| Messaging API Channel | ผูกกับ LINE OA ที่ใช้งาน |
| Channel secret | ตรวจลายเซ็น webhook |
| Channel access token | ดาวน์โหลดรูป/ไฟล์และตอบข้อความ |
| Webhook URL | เช่น `https://expense.example.com/api/line/webhook` |
| LIFF ID (ถ้าเลือก A) | เปิด mobile form ผ่าน Rich Menu |
| Rich Menu | ปุ่ม “เพิ่มค่าใช้จ่าย”, “รายการของฉัน”, “เชื่อมบัญชี” |

ระบบตรวจพบว่ามี LINE connector ให้เลือกใช้ใน workspace แต่ยังไม่ได้เปิดใช้งาน การสร้าง feature ในเว็บไม่ควรพึ่ง connector นี้เป็นหลัก เพราะ webhook ต้องเข้ามายัง application server ของคุณโดยตรง; connector เหมาะสำหรับงาน agent ที่จัดการข้อความภายนอกมากกว่า

## ขอบเขต implementation ระยะแรกที่แนะนำ

1. เพิ่ม schema `line_user_links` และ `line_webhook_events` พร้อม admin page สำหรับ link/unlink บัญชี
2. เพิ่ม webhook endpoint ที่ตรวจลายเซ็น, deduplicate event และรับ text/image file
3. ทำแนวทาง A หรือ B ตามตัวเลือก, แต่ให้สร้างได้เฉพาะ `draft`
4. เพิ่มปุ่ม Rich Menu และข้อความตอบกลับพร้อม deep link เข้า expense detail
5. เขียน test สำหรับ signature, event ซ้ำ, ผู้ใช้ไม่เชื่อมบัญชี, file size/type และการไม่สร้างรายการซ้ำ

## ข้อมูลที่ต้องยืนยันก่อนเริ่มพัฒนา

กรุณาเลือก **A (เปิดแบบฟอร์มมือถือ)** หรือ **B (พิมพ์ข้อความ/แนบรูปในแชต)** ก่อน จากนั้นต้องมี LINE OA ที่สร้าง Messaging API channel แล้ว, domain HTTPS ที่พร้อมรับ webhook, และ Channel secret กับ Channel access token ซึ่งควรส่งผ่านช่องจัดการ secrets ที่ปลอดภัย ไม่ควรส่งค่า token ในแชต
